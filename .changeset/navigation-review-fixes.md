Navigation fixes from an adversarial review. A NotFound fallback now takes the shortest run of segments after which the rest parses, so a page pushed above it keeps its own route: `/counter/nope/session` parses back as NotFound with Session above it instead of one longer NotFound. A lifted child route is allowed above a Destination the child does not know, so `/counter/menu/session` round-trips. A URI fragment is dropped before parsing. The carrier's three-write limit now counts writes in a row that leave the carrier short of the plan, so a Program that refuses Back again and again keeps being corrected, and it reports giving up once. `MirrorNavigation` returns every device to the first screen at its log position, so devices that kept their own screens meet again. `Navigation.openWhenReady` sends a URI once a Program is Ready, and OpenTUI and `useDeepLinks` use it, so a deep link that arrives while Starting is kept. `Navigation.ownsUri` and the bound interaction's `ownsUri` say whether a URI is the Program's, and `NavigationFrame` opens only those links, and only on a plain primary click. `CarrierEntry.title` is now `maybeTitle` and a route's `titleOf` is `maybeTitleOf`, both `Option`. `NavigationFrame` repaints a layer only when its own view changes, `useBrowserHistory` no longer restarts its carrier when `onDiagnostic` changes identity, `FoldkitRouter` renders nothing rather than inventing a location, and `useIsNavigationReady` lets both native stacks mount on readiness instead of re-rendering on every move. `entryOptionsOf` and `EntryView` are shared by both native stacks. The CLI refuses `open` without a URI, and its help and the OpenTUI hint no longer name Counter routes or menu keys.
