A Program becomes a command with one call. `terminal()` from the new `foldkit/cli/host` is the whole of a terminal host: `await terminal({ name: 'counter', entry: import.meta.url, processor: async () => ({ program: SyncedCounter, start: host => startCounter({ host, instance }) }) })`. It starts the host's own entry again as the Background Processor on the first command, so a command never imports the Program, and it owns `stop`, `watch`, `tail`, `tui`, `follow <topic>`, and every word the Program declares. The Background Processor stops by itself after ten minutes with no work the host's `keepsAlive(model)` names, no view attached, and no command (`foldkit/cli` exports the rule as `quietAfter` and `isGraceOver`). `stop` now travels over the socket, runs the host's `beforeStop` while the Program is alive, and answers before the process ends. A command from a rebuilt host replaces the older Processor, and a checkout elsewhere never takes it over.

The listener is safer for every host: it removes the socket, pid and lock only when they are its own (`removeOwnCliDaemonFiles`), the spawn lock names the process that was started (`holdCliDaemonLockFor`), a connection that never sends its request is dropped after five seconds, and `startCliDaemonServer` takes `onAnswered`.

`counter completions` installs tab completion for the shell it is run in (zsh, bash or fish), and `counter completions zsh` prints the script. The script holds no word of the Program's: on each Tab it asks `counter completions words`, which the Background Processor answers from the Catalog as it stands (`commandWordsOf`), so `counters increment` then Tab offers the counters there are.

A Background Processor whose Program has work going on is no longer replaced by a command from another build. The words a host's `keepsAlive(model)` gives hold off the replacement as they hold off the idle exit: the running Processor answers the command, the command says on stderr which work keeps it, and the first command after the work ends replaces it. `counter stop` still ends it at once. A Processor that does not say whether it is working within five seconds is left as well.

A host that must always be up says `lifetime: 'AlwaysOn'`. Its Background Processor never stops for having nothing to do, and `counter background install` writes a launchd agent that starts it at login and again whenever it ends any way but cleanly (macOS only). `counter background` says how the Processor is, without starting it, and `counter background uninstall` removes the agent. `launcher` names the script that starts the host with its environment. `terminal()` takes the login items port as a third argument, so a test never adds a login item to the person running it (the `LoginItems` type from `foldkit/cli/host`).

`Processor.Host` has a `Server` case, and a Subscription or ManagedResource entry can say `runsOn: Processor.RunsOn.serverOnly`: the runtime starts it only on a Processor whose Host is `Server`, and nowhere when the Host is not known. `makeProgramRuntime` takes `host`, and `Runtime.start` reads it from the sync engine's processor name. An always-on terminal host starts its Program on `Server`. Code that matches every `Processor.Host` case must add `Server`.
