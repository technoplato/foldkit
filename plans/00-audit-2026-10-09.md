# Audit | Counter family and platform adapters | 2026-10-09

Scope: `examples/counter`, `examples/multiple-counters`, the legacy
`examples/counters`, and `packages/{foldkit,react,svelte,opentui,react-native}`
on branch `claude/platform-adapter-packages` (equal to `technoplato/main` on
2026-10-09). Every claim below was checked by reading the named file. Tests at
the time: Counter core 27 passing, Multiple Counters core 24 passing, React
adapter 47 passing, both React hosts typecheck. Revised after adversarial
rounds 1 to 4 (R2-17, R2-34, R3-21, R4-20).

The goals are the owner's, from the messages in `plans/user-messages/`. Each
section ends with the plan that closes it.

## 1. Zero business logic in hosts

Done for every host of Counter and Multiple Counters except the terminal.

- `examples/counter/react/src/App.tsx` is 37 lines and names no Action, route,
  or word; `examples/multiple-counters/react/src/App.tsx` is the same file.
  Svelte, Expo, Expo Router, OpenTUI, and TUI entries have the same shape.
- The Counter CLI is 7 files (`entry`, `daemon`, `session`, `settings`,
  `inProcess`, `tail`, `watch`, about 255 lines) of socket, tape, and daemon
  plumbing. Books' CLI is 8 source files and 807 lines, plus a 506-line
  test, on the same pattern. ADR 0014 Decision 1 says this collapses into one
  terminal runtime; nothing has moved yet. Multiple Counters' CLI is one-shot,
  which ADR 0014 names as the shape that killed Books' audio.
- `examples/counter/foldkit/src/view.ts` is 99 lines of hand glue (status
  matching, menu gestures, opener button) because the Foldkit HTML adapter has
  no `NavigationFrame` equivalent. It reaches the interaction with
  `Option.getOrThrowWith`.
- `examples/counter/react-bindings/src/counter.tsx` hand-maps
  `clickedIncrement` to `Increment()`; it is marked "retire with the showcase".
  20 `package.json` files carry a dependency line on a hand-mapped bindings
  package (`shared-react-bindings-example`, `counter-react-bindings-example`),
  and 40 on those two or the legacy `counters-core-example`, which plan 05
  retires (counted from `git ls-files`).

Closes in `plans/01-terminal-runtime.md`, `plans/03-react-canonical.md`,
`plans/10-hosts-matrix.md`.

## 2. The inverse leak: client details in core

- `examples/counter/core/src/companions.ts` hard-codes host ports (5216, 5218, 5215) and `pnpm --filter` commands into the Program's Session Sheet.
- `examples/counter/core/src/live.ts` reads `COUNTER_TAPE` and
  `COUNTER_TAPE_PATH`; the Memory and File tape switches span about 25 files
  (`VITE_COUNTER_TAPE`, `EXPO_PUBLIC_COUNTER_TAPE` included). `examples/AGENTS.md`
  forbids shipping examples that sync through Memory or a file.
- `examples/counter/core/src/startConfig.ts` types the start config on
  `InstantSnapshotLogDatabase`, so core knows Instant.
- `packages/foldkit/src/processor/host.ts` is a closed enum of 9 Hosts (Cli,
  Tui, OpenTui, Headless, Foldkit, React, Svelte, ExpoIos, ExpoAndroid). A new
  TUI framework means editing the library.
- `counterScreen(model, context: ActionContext = {})` takes an optional
  `device` whose kinds today are `watch`, `phone`, `tablet`, `computer`, and
  `tv` (`packages/foldkit/src/schema/index.ts`): optional presentation context
  in a core screen.

Closes in `plans/01-terminal-runtime.md` (App recipe replaces env reads),
`plans/06-sync-engines.md` (engine chosen by the host), `plans/02-action-declarations.md`
(total types).

## 3. The React escape hatch

`packages/react/src/interaction/interaction.tsx` has `useFeature(program, select, isEqual)` returning `{ model, actions }`. `useSelected` in `selected.ts`
caches per snapshot and keeps the reference while `Equal.equals` (structural in
Effect v4, checked in `repos/effect-smol/packages/effect/src/Equal.ts`) says the
selection is unchanged. `interaction.test.tsx` covers "re-renders a selection
only when its value changes".

Gaps:

- `actions` includes only payload-free Actions (`isPayloadFree`). Multiple
  Counters' `Increment({ counterId })`, `Open`, `Delete`, `ConfirmDelete` are
  absent; a component must call `bound.press(Catalog.choiceTagOf('Increment', '3'))` with a string.
- `FeatureModel<P>` is the synced gate union (`Starting | Ready | Failed`), so
  every selector branches on `_tag` (`model._tag === 'Ready' ? model.count : 0`
  is the documented example).
- `useBoundTo` throws when the Program passed is not the bound Program by id,
  and the bound Program in Multiple Counters is the composed
  `sync:actionMenu:session:multiple-counters`, so a component cannot bind the
  Counter inside it, and nothing scopes one row.
- Svelte's `reactive()` (`packages/svelte/src/interaction/reactive.ts`) has no
  selector; each getter re-subscribes the reading component to every change.

Closes in `plans/02-action-declarations.md` and `plans/03-react-canonical.md`.

## 4. Two React APIs

- Root `@foldkit/react` (`bindProgram`, `createProgramHooks`, `useModel(path, selector)`, `useScreen`, `sendScreenToken`, `ProgramKeyBindings`) keeps a
  module-global `slots` Map and a module-level `lastScreenTag`. 25 files in 9
  examples use it (settings, puzzle, ingest, casino, books, read-aloud, gate,
  songbook, issues).
- `@foldkit/react/interaction` (`ProgramProvider`, `useBound`, `useFeature`) is
  used by counter, multiple-counters, books, read-aloud, reminders, and
  `@foldkit/react-native`. Books and read-aloud import both.
- The root `useModel(path, selector)` passes `selector(model)` straight to
  `useSyncExternalStore` as `getSnapshot` with no equality, so an
  object-returning selector re-renders on every notify and trips React's
  "getSnapshot should be cached" check.

Closes in `plans/03-react-canonical.md`.

## 5. Navigation as state

Done. `NavigationStack { root, pages, maybeModal }` with a closed Destination
union, `PresentationStyle` (Push, Sheet, BottomSheet, FullScreenCover, Dialog,
Popover, Drawer with a side), `isAllowedAbove` rules, `foldMessage`,
`withoutDestinations`. Carriers: browser history (`useBrowserHistory`), React
Router (`FoldkitRouter` with app-owned pages such as `/about`), React Navigation
(`FoldkitStack`), Expo Router (`FoldkitRouterStack`), terminals
(`ownNavigationHosts`).

Gaps:

- No way to mount a Program under an existing app's prefix (`/legacy/counter`).
  `FoldkitRouter` creates its own `<Router>`, so it cannot sit inside an
  existing `<BrowserRouter>`.
- No Tabs (parallel stacks), no drawer container, no declared shell (sidebar,
  dock), no stack inside a presented Sheet, no leave guards.

Closes in `plans/04-navigation.md`.

## 6. One core, every surface

Counter: 10 hosts. Multiple Counters: 5 (React, Svelte, CLI, TUI, OpenTUI),
no Expo, no Foldkit HTML (its README says so). Closes in
`plans/10-hosts-matrix.md`.

## 7. Tail with state changes

`counter tail` (`packages/foldkit/src/cli/tail.ts`) prints time, app, instance,
and the Message, and by design never applies it, so it cannot print changes.
`Program.modelChangeLines` (`packages/foldkit/src/program/changes.ts`, TCA
`_printChanges` style) is used only by
`examples/counter/headless/src/print.ts`, names leaves by array index, and is
quadratic in the leaf count. The daemon protocol
(`packages/foldkit/src/cli/protocol.ts`) already returns `{ model, previous }`
from `Run`. Closes in `plans/01-terminal-runtime.md`.

## 8. Actions with places, plain English, generated skills

`Catalog.action` carries `what`, `why`, `enabled` with a `because` sentence,
`meta.label`, `meta.keys`, optional `meta.title`, and `choose`. Nothing names
where an Action is offered; each `screen` and `viewOf` hand-picks tags
(`entriesTagged(Catalog.entries(catalog, model), [Add.tag])` in
`examples/multiple-counters/core/src/screen.ts`). No markdown adapter exists.
The 14 skills under `skills/` are hand-written. `packages/devtools-mcp` exposes
generic tools (`foldkit_dispatch_message`, `foldkit_get_message_schema`), not
per-Action ones. `programUsage` in `packages/foldkit/src/cli/program.ts` is the
only generated prose. Closes in `plans/02-action-declarations.md`,
`plans/07-static-graph.md`, `plans/08-skills-and-finance.md`.

## 9. Composition as ergonomic as TCA

Primitives exist: `Program.compose`, `compose.forEach`, `scope`,
`Catalog.lift`, `Catalog.within`, `Session.compose`, `ActionMenu.compose`,
`Program.compose.sync`, `Navigation.composeNavigation`. But
`compose.forEach` (`packages/foldkit/src/program/compose.ts`) composes Model,
Message, init, and update only; its config is `of`, `initialCount`, `fields`,
`initialFields`, `messages`, `updateFields`; its rows are `{ id: string, child }` with `id` minted from `nextId` inside the fold. Nothing lifts
catalog, navigation, screen, or synchronization, and `Catalog.lift` drops a
child Action's own fields, so only payload-free children lift. Multiple
Counters therefore hand-rolls: `update.ts` (154 lines) with `withCounter`,
`countedBy`, `counted`, `openedCounter`, `askedToDelete`, `deletedCounter`;
`message.ts` (167 lines) with two hand-written `Choose` configs;
`program.ts` with a hand-written `categoryOf`.

A correctness bug comes with both the hand-rolled version and today's
`forEach`: an id minted from a counter inside the fold is reassigned when a
row that lands late with an earlier `createdAtMs` triggers a refold (ADR
0013), after which a logged `Increment({ counterId: 1 })` counts whichever
counter is first now. Messages stop being facts. Closes in
`plans/05-composition.md` (ids minted by the sender, plan 02).

## 10. Cross-language protocol

Implemented twice in TypeScript, specified nowhere:

- `packages/instant/src/programLog/programLog.ts`: `ProgramMessageRow { id, app, programVersion, tag, payload, from, createdAtMs }` on table
  `programMessage`, with no `seq`, no actor, no owner.
- `packages/instant/src/snapshotLog/messageWire.ts`: the older Counter V01
  layout packs the payload into the `tag` column as `Tag:{json}` on tables
  `count` and `message`.
- `packages/foldkit/src/cli/protocol.ts`: a Node-only daemon protocol (Read,
  Run, Show, Do; Ok, Painted, Failed; version 1).
- `from` is `<host>-<instance>` (ADR 0011 Q107), parsed by `includes('-mine-')`
  and by longest known host prefix. Row order is `createdAtMs`, then `from`,
  then `seq`, then `id` (`runtime/syncEngine.ts`), with `from` and `seq`
  optional for legacy rows. `instance` is 32 random bits per run.
- Swift (`technoplato/counter-swift`) and Rust (`technoplato/tca-rust-port`)
  readers live in sibling repos pinned in ADR 0011's README; the owner reports
  they did not work. Audited by reading in `plans/09-cross-language-protocol.md`.
- No JSON Schema export of a Program's Message for codegen;
  `packages/foldkit/src/devTools/schemaSummarize.ts` summarizes for display.

## 11. Sync engine and snapshot models

- `Runtime.SyncEngine` (`runtime/syncEngine.ts`) is Instant-shaped: `read()`
  returns `{ snapshot: unknown | undefined, messages }`; `write()` takes `{ snapshot, message }`, so every write stores a snapshot row; `readSince?` is
  optional; `SyncEvent` is `Snapshot | Message`. The doc comment says "Instant
  I/O surface" and "Memory is a fake Instant".
- `@foldkit/instant/src/sync/fromTransport.ts` is the seam: an engine is built
  from a `SnapshotLogTransport`. Nothing else implements that transport.
- Instant's read cursor is a count of rows in `serverCreatedAt` order, and
  Instant's server stamps that column with the transaction's start time, so
  a row that starts first and commits last can land behind a cursor already
  read.
- ADR 0013 made local snapshots a per-device cache with watermarks; the shared
  `count` row is still written "for counter-swift and the Rust reader. Boot
  never reads it." Q109 (compaction) is open. TypeScript disagrees with itself
  on the row's `asOf` (`start.ts` writes the Processor id, `snapshotLog.ts`
  the Message id).
- `LogRowOrder` has optional `from` and `seq`; the envelope has no actor and
  no owner.
- All three Instant targets are Instant Cloud apps, which close on 2027-08-31.

Closes in `plans/06-sync-engines.md`.
