Foldkit invariant

I understand that we want everything to be platform agnostic and especially framework agnostic.

Native stacks, browser history, terminals, and any future host are adapters around one portable Program.

Your strongest points

The navigation bridge needs causality.

1. Expo cannot silently own Back

We must distinguish a transition requested by the Program from one caused by a swipe, hardware Back, deep link, or another host event.

2. The app is a typed graph

Routes are nodes. Allowed transitions are edges. A Back action is valid only when the graph connects the current and proposed destinations.

3. Presentation is portable

A button, notification, text edit, audio-level change, or other interactor can be described as a cause that sends a typed Message.

4. Deep links may carry intent

A route can reconstruct visible state and carry a typed set of pending Messages. Those Messages still enter through update.

Proposed correction

One transition protocol, with origin and acknowledgement.

sequenceDiagram
  participant Input as Button, swipe, Back, deep link

  Adapter->>Program: AttemptedNavigation(from, to, cause)
  Program->>Program: validate graph edge
  Program-->>Adapter: Model selects B, revision 7
  Adapter->>Expo: apply B for revision 7
  Expo-->>Adapter: route state changed to B
  Adapter->>Adapter: acknowledge revision 7, send no duplicate Message

Important vocabulary

Anchor and pending Messages are different things.

Expo anchor

The background route that Expo reconstructs beneath a deep-linked modal. It gives the native modal somewhere to dismiss back to.

Foldkit route intent

Portable state plus typed pending Messages. Parsing produces an initialization value. update decides which Commands follow.

Where I align and push back

A portable presenter is useful. It cannot become mandatory.

Strong agreement

Ordered presentation choices can provide defaults. Causes map platform interactions to typed Messages. This is a portable presentation description, not HTML.

My pushback

If every Program must describe UI through this vocabulary, we have built another required view framework. The domain Program must remain consumable without it by React, native, CLI, TUI, Foldkit view, or a future host.

Graph detail

An adjacency matrix says which nodes connect. Each edge still needs a typed cause, target, guard policy, and whether the host should push, replace, pop, present, dismiss, or focus.

Security detail

Compression and hashes prove identity or integrity. They do not hide private state or authorize an operation. Encryption and signatures remain separate capabilities.

Human immune system

Do not optimize important communication for virality.

Human review finds the edge

Types and generators prove structural rules. People notice when the resulting behavior is technically valid but experientially wrong.

Friction can be protective

If something spreads widely, it should be important. Low-value material should not be made artificially irresistible or easier to amplify than its value warrants.

Decision 2

Should native Back be intercepted before Expo commits it?

Recommended: yes. Send an attempted-navigation Message, validate the graph edge in the Program, then let the adapter commit the native transition and acknowledge it.
