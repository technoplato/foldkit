Foldkit navigation exploration

The product UI and replay UI control the same Program.

These are interaction prototypes, not implementation. Try the real counter buttons, open detail, show a fact, request deletion, and then use the floating Replay control to scrub through those exact presentation states.

No React navigation state

React reads one Model through useModel. It never mirrors destination or modal state in useState.

Every close is a Message

Escape, backdrop, Cancel, Delete, and Dismiss all call useActions. The Program decides the next Model.

Replay is another controller

One ReplayController backs both hooks. useActions runs Messages, while replay controls inspect and seek the same Model stream.

Two presentation mappings

Same domain, different React adapters

Both are valid. The decision is whether every presentation uses one generic modal shell, or whether each destination case selects the platform surface that best fits its meaning.

Presenter contract

What stays in React

  • 1Exhaustively map the destination case to a React screen, modal, sheet, or confirmation dialog.
  • 2Translate native dismiss signals into Dismissed or Cancelled Messages.
  • 3Reconcile browser history and native dialog mechanics from Model changes.
  • 4Keep focus trapping, inert content, scroll locking, and animation as host concerns.
  • 5Never decide whether fact or delete is valid. The Program and current sum-type case already decided.
  • 6Do not run a second replay workbench beside the app. Product controls and replay controls share one controller and one observable Model.
